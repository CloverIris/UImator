# 开工前的三个尖峰

这三个尖峰的目的不是「做个 demo」，是**用最小成本证伪**。每一个都有明确的失败判据，失败就停下来改 ADR，而不是继续堆功能。

时间盒：每个尖峰 3 天，超过就说明范围切得不对。

---

## S1 捕获保真度尖峰

**要回答的问题**：CDP 截图这条路，在真实长尾站点上到底能覆盖多少？两遍重截的分辨率上限在哪？

**做什么**

1. 一个最小 Electron 应用：地址栏 + `WebContentsView` + CDP 连接。
2. 冻结补丁（ADR-0007 的核心子集：rAF / Date / CSS 动画 / 随机）。
3. 点选元素 → `Emulation.setDeviceMetricsOverride` 设 3x → `Page.captureScreenshot` 带 clip → 存 WebP。
4. 一个脚本，对 12 个站点批量跑：选 8 个候选元素，各截 3x，记录耗时、失败原因。

**测试集（12 个，覆盖长尾）**

| # | 类型 | 考察点 |
| --- | --- | --- |
| 1 | 静态落地页（Astro） | 基线 |
| 2 | Next.js SSR 营销页 | 字体、图片 |
| 3 | React dashboard（shadcn） | 层叠、圆角、阴影 |
| 4 | Vue 后台（Element Plus） | 组件库样式注入 |
| 5 | 含 ECharts 的页面 | canvas 内容 |
| 6 | 含 WebGL 图表的页面 | 合成层 |
| 7 | 含跨域 iframe 的页面 | 空白/占位 |
| 8 | 含虚拟滚动的列表页 | 不完整 |
| 9 | 中文站点（思源黑体） | 字体与行高 |
| 10 | 深色主题 + 毛玻璃 | `backdrop-filter` |
| 11 | 有 cookie 横幅 | 干扰项 |
| 12 | Cloudflare 保护站 | 拦截 |

**通过标准**

- ≥ 9/12 站点能截出**无变形、无缺块**的素材。
- 特写素材 6x 下，中心区域与源页面同尺寸重渲染的 SSIM ≥ 0.92。
- 单页 8 素材 3x 截图 ≤ 15 s。
- 同页连续 50 次截图，像素哈希一致率 100%。
- 记录每个失败站点的具体原因（这比通过率更重要）。

**失败时怎么办**

- 若 SSIM 不达标：检查是否被 `deviceScaleFactor` 上限截断，或元素有 `transform` 导致 clip 坐标错位。
- 若一致率不达标：说明冻结不完整，逐个排查定时器/动画源。
- 若覆盖率 < 60%：ADR-0002 需要重审，考虑「捕获端插件」形态。

## S2 舞台观感尖峰（唯一的 go / no-go）

**要回答的问题**：从真实 DOM 拆出来的图层，做 3D 爆炸、运镜、景深，**到底好不好看**？

这个问题没法用指标替代。如果答案是「不好看」，后面所有工程都不必做。

**做什么**

1. 用 3 个 fixture 站点（自己可控）：一个 SaaS 落地页、一个 dashboard、一个定价页。
2. 各拆 6–10 个素材（手工点选，不做自动聚类）。
3. three.js 舞台：卡片挤出 + 接触阴影 + 侧面色 + 景深 + 辉光 + 颗粒。
4. 一个 8 秒镜头：`全景倾斜入场 → 爆炸展开 → 推近一张卡片 → 收束`。
5. 输出 1080p60。

**通过标准（盲测）**

找 10 个不知道内情的人看，问三个问题：

1. 「这像不像花钱做的宣传片？」—— ≥ 7 人「像」。
2. 「卡片是浮在空间里的，还是贴在墙上的？」—— ≥ 7 人「浮着」。
3. 「和 Linear / Vercel 那种片子比，差在哪？」—— 收集具体描述，不设阈值。

**同时做的 A/B**

- 卡片厚度：2 / 4 / 6 px
- 接触阴影：无 / 弱 / 强
- 侧面色：纯黑 / 边缘采样
- 背景：纯色 / mesh gradient / 色彩采样

每组 3 档，看哪一档被人稳定识别。**如果差异无法被稳定识别，说明这些参数是无效做功，应该从产品里删掉，而不是做成滑杆。**

**失败时怎么办**

- 若「像贴纸」：优先怀疑景深与阴影，而不是几何精度。
- 若「像 PPT」：问题在节奏与构图，不在渲染，回到 ADR-0005 的 Director。
- 若整体不成立：产品需要重新定位（可能只剩「录屏增强 + 文字排版」这条更窄的路）。

## S3 导出与性能尖峰

**要回答的问题**：WebCodecs 这条路能不能在目标时间内跑完 4K60，且逐帧确定？

**做什么**

1. 隐藏窗口 + 固定步长循环 + `VideoEncoder` + `mp4-muxer`。
2. 场景：20 个图层、景深、辉光、颗粒、一个环绕镜头。
3. 三档导出：1080p60 / 4K60 / 4K60 + 2x SSAA + S=4 累积。
4. 中断续渲：杀掉进程，重启，续渲，比对最终文件。

**通过标准**

| 项 | 标准 |
| --- | --- |
| 1080p60 × 30 s | ≤ 4 分钟 |
| 4K60 × 30 s（2x SSAA, S=4） | ≤ 18 分钟 |
| 峰值显存 | ≤ 4 GB |
| 同机两次渲染同一帧 | 像素哈希一致 |
| 断点续渲 | 最终文件与不中断版本逐帧一致 |
| 音画同步 | 片尾误差 ≤ 1 帧 |

**失败时怎么办**

- 若 4K 超时：先砍 S（累积子帧），再砍 SSAA 到 1.5x；两者都不能砍则改「分块并行渲染」。
- 若哈希不一致：检查是否有 `Math.random` 漏网、纹理是否在帧内异步加载、`VideoFrame` 是否在绘制完成前创建。
- 若隐藏窗口吞吐异常低：改用「可见但移出屏幕」的窗口，或直接上离屏渲染（OSR）。

## 一周排期建议

| 天 | 内容 |
| --- | --- |
| D1 | S1：Electron 骨架 + CDP 截图 + 冻结补丁 |
| D2 | S1：12 站点跑批，出报告 |
| D3 | S2：fixture 拆解 + 舞台搭起来（先不做后期） |
| D4 | S2：后期 + 8 秒镜头 + 盲测 |
| D5 | S3：导出管线 + 三档测试 |
| D6 | 补测、修 ADR、写结论 |
| D7 | 决策会：继续 / 改方向 / 停 |

## 决策会要看的东西

不是「进度」，是三个数字：

1. S1 的覆盖率（≥ 9/12？）
2. S2 的盲测通过人数（≥ 7/10？）
3. S3 的 4K 导出耗时（≤ 18 分钟？）

三个都过 → 进入 MVP 开发。
S2 不过 → 产品方向重审，其余两个再好也没用。
S1 或 S3 不过 → 回到对应 ADR 改选型，不影响产品方向。
