# ADR-0004 素材模型：贴图 + 深度语义 + LOD + 文字策略

- 状态：待尖峰 S2 验证
- 日期：2026-10-26
- 关联：ADR-0002、ADR-0003

## 背景

捕获到的是一张位图，但舞台上需要的是「一张会在空间里浮起来的卡片」。从位图到可编排实体，中间缺三样东西：**厚度、深度、光源下的行为**。同时，页面里的文字（位图，糊）和用户自己写的文案（必须清晰）是两类完全不同的东西，不能用同一套方案。

## 1. 素材实体的字段

```ts
type Asset = {
  id: string
  kind: 'card' | 'panel' | 'bar' | 'overlay' | 'media' | 'fragment'
  texture: TextureRef          // content hash + LOD 层级表
  intrinsic: { w: number; h: number }   // CSS px，来自 getBoundingClientRect
  radius: number               // 来自 computed border-radius
  depthClass: DepthClass       // 决定初始 Z，见下
  depthBias: number            // 用户手动覆盖
  geometry: 'plane' | 'extruded-rounded'
  thickness: number            // 2–6 px（世界单位 = CSS px）
  sideColor: string            // 从素材边缘采样，用于侧面
  shadow: { mode: 'contact' | 'map' | 'none'; strength: number }
  alpha: 'opaque' | 'cutout' | 'premultiplied'
  recipe: CaptureRecipe        // ADR-0009
}
```

## 2. 深度语义：Z 从哪来

初始 Z 不能靠用户手工拉，必须有一个**可解释的默认值**，否则「一键爆炸」不成立。

推断信号（按权重）：

| 信号 | 含义 | 权重 |
| --- | --- | --- |
| `position: fixed` / `sticky` | 悬浮于内容之上 | 强 |
| 祖先新建了层叠上下文（`transform`/`filter`/`isolation`） | 视觉上叠了一层 | 强 |
| `box-shadow` 的 blur / spread 越大 | 离底板越高 | 中 |
| `z-index` 在兄弟中的相对位次 | 层序 | 中 |
| DOM 嵌套深度 | 越深越靠前（弱先验） | 弱 |
| 是否为「卡片类」（圆角 + 阴影 + 独立背景） | 实体化程度 | 中 |

归一化到四档：`background(0) / container(20) / card(60) / overlay(110)`，单位是世界单位（1 = 1 CSS px @ 参考平面）。用户可整体缩放「爆炸强度」，单素材可 `depthBias` 覆盖。

**不要**用真实 z-index 直接映射：z-index 是层内局部量，跨子树不可比，直接映射会得到一堆离散跳变。

## 3. 几何与材质：什么叫「浮起来了」

四件事决定观感，缺一件就像贴纸：

1. **厚度**：圆角矩形挤出 2–6 px（镜头越近越厚），带 0.5–1.5 px 倒角。
2. **接触阴影**：在卡片下方 z 略低处放一张模糊的暗色圆角面片，随卡片与底板距离变淡变大。这比真实阴影贴图便宜且好看。
3. **层间 AO**：相邻两层之间沿边缘加一道软暗角（预烘在纹理里或屏幕空间处理）。
4. **侧面颜色**：从素材四边采样均值，作为侧面与背面的材质色。避免纯黑或纯白侧面造成的「纸片」感。

**UI 面片本身不接受场景光照**（`unlit`）。UI 的颜色是设计稿定死的，被灯光染色就脏了。光照只作用于侧面、投影与环境。

## 4. LOD 与两遍重截

每个素材维护一条层级表：`1x / 2x / 3x / 6x / 10x`，按需生成。

- 编辑期一律用 `≤2x`；离屏或超过 800 ms 未使用则降级到 `1x`。
- 导出前跑一遍 **需求扫描**：对每个素材，遍历所有镜头，计算它在画面上的最大像素宽度 `Wmax`，选满足 `LOD * intrinsic.w >= Wmax` 的最低层级。
- 尚无该层级时，触发**第二遍重截**（回到源页面；见 ADR-0002）。
- 单张纹理超过 GPU 上限（通常 8192）时，按网格分块成多张贴图拼接，或降低倍率并对该素材启用锐化。

## 5. 文字：两类文字，两套方案

这是全栈里最容易做错的地方。**「页面里的字」和「你要写的字」不是同一种东西。**

### 5.1 被抓取页面里的文字 → 位图

它是 UI 的一部分，跟卡片一起被截下来。清晰度靠高倍率重截解决（ADR-0002）。不做矢量化：webfont 授权、缺字、富文本混排的成本远大于收益（尖峰 S1 中验证中文在 6x 下是否可接受）。

### 5.2 UImator 自己排版的文案 → MSDF

标题、卖点、CTA、字幕，必须任意倍率清晰、可即时改字、可做逐字动画。

- 字体：用户选本地 TTF/OTF（系统字体目录 + 拖入文件）。
- 字形：`opentype.js` / `harfbuzzjs` 取轮廓 → msdfgen（WASM）生成 **按用字子集** 的图集。
  - 中文必须子集化：只生成文案里出现过的字，通常 < 200 个，图集可控；出现新字时增量补进图集。
  - 缺字回退链：指定 fallback 字体 → 再缺则用豆腐块并**在 UI 里报警**，绝不静默。
- 排版：**借浏览器做换行**。把段落塞进一个隐藏但已加载的 DOM 元素，用 `Range.getClientRects()` 拿到每行的断点与基线，再映射成 MSDF 字形四边形。这样中英混排、标点挤压、`text-wrap: balance` 这些细节不用自己实现。
- 动画：逐字 / 逐词 / 逐行的位移、透明度、模糊、遮罩擦除。全部由时间轴参数驱动（ADR-0005），不做 CSS 动画。

### 5.3 为什么不用 SDF 直接光栅化整段文字

- 整段光栅化 = 分辨率绑定，4K 特写会糊，等于回到位图问题。
- MSDF 的代价是只支持基本字形变形（描边、斜体模拟可用，复杂连字要靠 harfbuzz 预处理），对宣发片完全够用。

## 6. 后果

**正面**

- 素材模型足够简单（纹理 + 平面 + 少量参数），渲染侧好优化。
- 深度有默认值，「一键爆炸」是真的能一键。
- 文字清晰度与可编辑性同时拿到，且中文字体成本可控。

**负面**

- MSDF 管线是自研工作量最大的一块（图集管理、增量补字、换行映射、动画分层）。
- 位图素材无法适配极端特写（10x 以上），需要分块或接受轻微柔化。
- 素材与源页面强绑定，源页面消失则高倍率层级不可再生。

## 验证方式（尖峰 S2）

做 3 个 fixture 站点，各出一条 8 秒片，闭眼给 10 个人看，问两个问题：

1. 「这像不像花了钱做的宣传片？」——≥ 7 人答「像」才继续。
2. 「这些卡片看起来是浮在空间里的，还是贴在墙上的？」——≥ 7 人答「浮着」才继续。

同时量：卡片厚度/阴影/侧面色三组参数各取 3 档做 A/B，确认差异可被人眼稳定识别（否则说明我们的「实体感」参数是无效做功）。
