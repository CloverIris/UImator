# ADR-0002 捕获策略：CDP 位图优先 + 导出期两遍重截

- 状态：待尖峰 S1 验证
- 日期：2026-10-26
- 关联：ADR-0001、ADR-0004、ADR-0009

## 背景

「把页面上的一个卡片变成舞台上的一个图层」有两条根本不同的路线：

- **重建**：把 DOM 子树序列化成自包含的 HTML / SVG，保留文字与矢量，进入舞台后再排版。
- **截取**：直接把该区域按目标分辨率截成位图。

这条决策决定了后续一切：能不能改文字、4K 特写糊不糊、素材多大、导出要不要回到浏览器。

## 决策驱动

- 保真度：canvas、WebGL、跨域图片、webfont、伪元素、shadow DOM 都要正确
- 版面正确性：摘出来的元素不能变形
- 分辨率上限：镜头推近到 4K 满画幅时不糊
- 实现成本与长尾站点覆盖率
- 导出可重复性

## 备选方案

### A. DOM 序列化重建（html-to-image / foreignObject / 内联计算样式）

**致命问题不是渲染，是版面。** 一个卡片的尺寸往往由父级的 flex / grid / 百分比 / `min-content` 决定；摘出来的一刻，这些约束全部消失。再加上层叠上下文（`transform`、`filter`、`isolation`、`opacity<1` 都会新建）、`position: sticky`、祖先的 `overflow` 裁剪、`zoom`、CSS 变量继承链——要正确还原创作者的意图，等价于重写一个浏览器排版引擎的子集。

其余问题：webfont 授权与子集化、伪元素、shadow DOM 样式作用域、`background-image` 的 CORS、CSS-in-JS 的运行时样式、canvas 内容无法序列化。

结论：**长尾不可收敛**，做 demo 很惊艳，做产品会被无穷的站点打穿。

### B. CDP 合成器截图（选定）

```
Emulation.setDeviceMetricsOverride({ width, height, deviceScaleFactor: 3 })
Page.captureScreenshot({ format: 'webp', quality: 92, clip: { x, y, width, height, scale } })
```

- 截的是**合成器的输出**，页面里是什么就截到什么：canvas、视频、iframe、跨域图片、毛玻璃、伪元素，全部正确。
- **不受 canvas 跨域污染影响**——污染只作用于 `toDataURL()` 这种 JS 读像素的路径，浏览器截图不走那条路。
- 不需要 `webSecurity: false`，不需要改响应头，不需要动 CSP（注入走隔离世界或 `Page.setBypassCSP`）。
- 版面零重建：宽高就是它在页面上的宽高。

代价：**丢掉了文字可编辑性**，且分辨率被截图倍率锁死。

### C. 混合（位图 + 少量文字节点矢量化）

把 Hero 标题、按钮文案这类「一定会被读」的文字单独矢量化，其余仍用位图。

结论：方向正确，但**不是 v1**。它需要处理字体授权、缺字、行内样式、富文本混排，成本高于收益。留作 v2 的「文字可编辑」能力，且只对 UImator 自己排版的文字开放（见 ADR-0004）。

## 决策

1. **v1 全部走 B（CDP 位图）**，`deviceScaleFactor` 取 2–4，按素材的预计最大屏幕占用决定。
2. **引入两遍重截（two-pass re-capture）**：编辑器里用 1–2x 贴图保证流畅；导出前扫描时间轴，计算每个素材全片的最大屏幕像素面积，回到源页面用对应倍率重截一次。
3. 每个素材必须保存完整的**重截配方**（见 ADR-0009），否则第二遍无从谈起。

### 为什么两遍重截是关键

一张 420 CSS px 宽的卡片，镜头推近到占满 3840 px 宽的画面，需要约 **9.1 倍**。一次性截图在 3x 时只有 1260 px，推近必糊；而全程按 9x 截，显存直接爆（单张 3.8 GB）。

两遍重截把「编辑流畅」和「成片清晰」解耦：

| 阶段 | 倍率 | 目的 |
| --- | --- | --- |
| 编辑预览 | 1–2x | 60fps 拖动 |
| 导出（远景素材） | 2–3x | 够用即可 |
| 导出（特写素材） | 按需 6–10x，必要时分块拼接 | 4K 满画幅不糊 |

这是「手里有一个活的源页面」才具备的能力，也是相对 AE 的结构性优势。

### 附带能力：图层剥离

为了在舞台上把卡片浮起来，底板不能还画着这张卡片。做法是**再截一张「抽掉该节点」的底板**：

```
Node.prototype.__uimatorHide = true   // 或 visibility: hidden
→ 截底板 → 恢复
```

注意：如果该卡片曾经遮挡过其他内容，抽掉后底板会出现一块空洞。因此底板修补限定在「卡片背景近似纯色或可平滑外推」的情况下自动启用，否则把卡片在底板上的位置标记为已知区域，由渲染层的阴影/辉光遮住。**不要承诺「无损分离」**，那是图像修复问题。

## 理由

保真度与长尾覆盖率压倒性优于 A；分辨率问题用两遍重截解决；文字可编辑性是唯一损失，而它在 v1 的价值远低于「页面拆出来不变形」。

## 后果

**正面**

- 任意站点、任意技术栈，只要能渲染就能截。
- 版面零风险：所见即所得。
- 素材是纯位图，渲染侧实现简单（纹理 + 平面）。
- 第二遍重截让 4K 输出质量与源页面分辨率解耦。

**负面**

- 素材体积大（120 个 × 2–8 MB），必须有 LOD 与磁盘缓存策略。
- 导出依赖源页面仍可访问、且状态可复现；离线工程只能出低倍率版本。
- 无法改文字。用户想改卡片里的一个错别字，只能回源页面改。
- 两遍重截带来导出时长增加与失败面（页面改版、登录过期、A/B 实验）。

**风险缓解**

- 素材失效检测：截图时存感知哈希；重截后比对，漂移超阈值则标记「素材已过期」，中止导出并提示。
- 状态复现失败时降级为「用缓存的高倍率纹理」，并在导出报告里注明。

## 验证方式（尖峰 S1）

选 12 个真实站点（SSR 落地页 / React dashboard / Vue 后台 / 含 ECharts / 含 WebGL 图表 / 含跨域 iframe / 含虚拟滚动 / 中文站点 / 深色主题 / 有 cookie 横幅 / 有 Cloudflare / 有 shadow DOM 组件库）：

- 命中率：能截出**无变形、无缺块**素材的站点数 ≥ 9/12
- 清晰度：特写素材在 4K 满画幅下，与源页面同尺寸渲染的 SSIM ≥ 0.92
- 耗时：单页 15 秒内完成 8 个素材的 3x 截图
- 稳定性：同一页面连续截 50 次，感知哈希一致率 100%
