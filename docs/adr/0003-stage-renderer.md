# ADR-0003 舞台渲染：全 WebGL，不用 CSS3D

- 状态：已接受
- 日期：2026-10-26
- 关联：ADR-0002、ADR-0004、ADR-0006

## 背景

舞台上要同时出现几十个 UI 图层、一个可自由运动的虚拟相机、景深、辉光、颗粒、色差、接触阴影，并且最终要逐帧导出 4K。

three.js 生态里有两条经典路线：`CSS3DRenderer`（用 DOM 承载内容）与 `WebGLRenderer`（全部进 GPU）。也有大量项目用「WebGL 背景 + CSS3D 前景」的混合。

## 决策驱动

- 「贵感」= 统一的后期处理，而不是单层效果
- 深度正确性（遮挡、排序、阴影、AO）
- 逐帧导出的确定性与速度
- 超过窗口尺寸的渲染能力（4K / 超采样）
- 图层数量上限

## 备选方案

### A. CSS3D

**优点**：文字无限清晰、原生字体渲染、可以直接放真实 DOM。

**致命缺点**

1. **拿不到统一后期。** 辉光、景深、颗粒、色差、暗角、运动模糊都必须作用在**整张画面**上，而 CSS3D 的每层是独立的合成层，只能各自套 CSS `filter`。逐层做景深的结果是「每张卡片自己糊」，而不是「空间里有焦点」——这是廉价感和高级感的分界线。
2. **深度关系是假的。** CSS3D 用 `matrix3d` 做透视除法，浏览器按层排序合成，跨层像素级遮挡做不到（会被拆成交错的多边形或直接错序）。
3. **导出不可控。** 逐帧导出要靠 `capturePage` 或 `Page.captureScreenshot`，DOM 合成是异步的，容易出现帧与帧之间不一致；而且**渲染尺寸被窗口限制**，4K 与超采样都做不到。
4. **层数一多就崩。** 每个 CSS3D 元素都是一个合成层，60 层 + 模糊滤镜，GPU 内存与合成时间都会爆。

### B. 全 WebGL（选定）

所有图层都是带纹理的网格，文字走 MSDF 或纹理。

**优点**：

- 一个 canvas → 后期一次做完 → 一次读回 → 一帧一帧确定。
- 真深度：深度缓冲、阴影贴图、SSAO、正确的透明排序。
- 任意分辨率：渲染目标可以大于窗口，直接支持 4K 与 2x SSAA。
- 图层便宜：一个图集 + 实例化，几百个平面不是问题。
- 运动模糊可以用子帧累积实现（见 ADR-0006），CSS3D 做不到。

**缺点**：文字不再是「浏览器排的」，要自己做排版与字形渲染（见 ADR-0004）。

### C. 混合（WebGL 背景 + CSS3D 前景）

看起来两全其美，实际上是**两边的缺点都占**：后期割裂、导出要同时驱动两套渲染器、深度无法互通、层数上限依旧。业界用它的场景是「文字很多、镜头不动」的静态展厅，不是「相机穿梭 + 分层爆炸 + 4K 导出」。

## 决策

**全 WebGL。** 舞台上不存在任何参与构图的 DOM 元素。`CSS3DRenderer` 不引入。

文字策略随之确定，但不属于本 ADR 的范围，见 ADR-0004：**UImator 自己排版的文案走 MSDF（矢量，任意倍率清晰）；被抓取的页面文字走位图（按 ADR-0002 的高倍率重截保证清晰）**。

## 理由

后期统一性 + 深度正确性 + 确定性导出，这三件事对「产品宣发片」是刚需，没有替代品。CSS3D 的清晰度优势在**视频输出**场景下可以直接用超采样买回来——因为我们不在实时帧率和显存之间做取舍，我们是在渲染时间之间做取舍。

## 后果

**正面**

- 后期链与 AE 的概念一一对应（Bloom / DOF / Grain / CA / Motion Blur），模板可迁移。
- 导出路径极简：`render() → canvas → VideoFrame → encode`。
- 支持 2x SSAA：4K 输出按 8K 渲染再缩，边缘与文字立刻上一个档次。

**负面**

- 必须自建文字管线（排版、换行、字形图集、缺字回退），这是本方案最大的一笔债。
- 必须自建阴影/接触阴影方案（真实阴影贴图在薄平面上效果差，通常要叠一层假阴影）。
- 40 层透明面片的排序与混合要小心（见下）。

**实现约束（写进代码规范）**

- 透明面片按相机距离排序，或统一用 `depthWrite: false` + 排序，避免 Z-fighting 与边缘黑边。
- UI 材质默认 `unlit`（`MeshBasicMaterial` 或自定义 flat shader），因为 UI 不该被场景光照改变颜色；只有卡片的**侧面/厚度**与投影接受光照，这样才有「实体感」而不脏。
- 卡片几何用圆角矩形挤出（2–6 px）+ 倒角，圆角半径取自 `border-radius`，否则放大后会看出是「贴纸」。
- 景深用 CoC 后处理；对「贴在焦平面上的薄片」要做边缘保护，否则透明边缘会出现剪纸感（尖峰 S2 验证项）。

## 何时重审

- 若 WebGL 的文字管线成为不可控的成本，可考虑把「文字层」单独拆成一个 2D canvas 叠加层，但**仅在导出时合成**，不做实时 CSS3D。
- 若未来需要「点击可交互的实时演示」，那是另一个产品形态，不在此架构内扩展。
