## 这一轮交付了什么

1. **自动拆解（扫描）**：遍历 DOM → 打分 → 去重 → 分类，产出候选池，左侧面板展示分数、尺寸、文本摘要与「为什么被选中」的理由标签，点击即可选中并高亮。
2. **6x 重截**：`Emulation` 倍率最高到 10x，单边超过 8192 px 时自动降倍率并写 warning，不会截出半张空白。
3. **悬停态采集**：走 CDP `Input.dispatchMouseEvent`（真实命中测试），先滚动进视口、再触发、再**校验 `el.matches(':hover')`**，失败重试一次，仍失败就记 `hover-not-applied`。
4. **工程持久化 + 配方复现**：每次捕获把「重截配方」写进 `projects/last.json`；`npm run recap` 按配方重新加载、重新冻结、重新截，比对像素哈希。
5. **真实站点矩阵**：`npm run matrix`，12 个站点自动跑「加载 → 冻结 → 扫描 → 截前 4 个候选」。

```

```

## 这一轮抓到的三个不确定性问题（都已修）

### 1. 我们自己的高亮遮罩会被合成进素材

选中候选时，页面上会盖一层「聚光灯」遮罩（`box-shadow: 0 0 0 9999px rgba(...)`）。如果紧接着截图，这层遮罩会被一起截进去，而且是半透明的——肉眼很难发现，只有哈希对比会暴露。

修法：每次截图前清掉所有 `[data-uimator]` 节点。

### 2. 悬停位移会让裁切框跟着动

`.feature-card:hover` 有 `translateY(-4px)`。如果裁切框在位移生效之后才测量，截出来的图是「对齐到新位置」的；如果在生效之前测量，就是「差 4px」。同一配方两次结果不同，差值恰好是 12 px（3x）。

修法：悬停后**校验 `:hover` 已生效**再测量；并把这一条写进了 `warnings`。

### 3. 上一次的悬停在这一次残留

鼠标停在卡片上截完图，下一次截相邻元素时，指针还压在那张卡片上——于是「非悬停」的素材里带着悬停效果。这类污染不会报错，只会让素材悄悄变形。

修法：每次截非悬停元素前，把指针挪到 (1,1) 并**轮询确认 `:hover` 已解除**，最多 8 次；失败就记 `hover-stale`。

> 这三条的共同点：**都不是渲染错误，而是状态残留**。它们只会在「同一流程跑第二遍」时暴露，所以 `recap` 这个看似多余的脚本，实际上是这一轮最有价值的产出。

## 已知不足（留给 R3 之前处理）

| 问题 | 现象 | 方向 |
| --- | --- | --- |
| 分类偏粗 | Linear 的全宽区块被标成「卡片」 | 加面积/长宽比阈值，把 `areaRatio > 0.25` 归到 section/hero |
| 嵌套重复 | 「v3.0 现已发布」同时以「区块」和「卡片」出现两次 | 包含抑制的阈值从「分差 > 10」改成「面积比 + 语义优先级」 |
| 纯表格页误判 | HN 的 `table` 整页被当成一个素材 | 表格应该按行切分，这是 R3 的「结构模板」问题 |
| 高分候选仍不够高 | 最高分 52（满分按 100 设计） | 分数只是排序信号，不必归一化；但面板上要显示相对排名 |
| 站点「通过」不等于拆得对 | Figma / X 通过是因为我们拿到的是落地页而非 canvas 应用/登录墙 | 需要 `expect` 与 `actual` 的对比列，而不是只统计 ok |

## 对 ADR 的反馈

- **ADR-0009（配方是真相）**：从纸面变成了可运行的东西，5/5 复现成功。配方里必须包含 `hover` 与冻结相位，否则复现不出来——这条要补进文档。
- **ADR-0007（确定性）**：新增两条硬约束：**截图前清掉自己的 DOM 注入**、**每次捕获前重置指针并校验悬停态**。这两条应该进 ADR-0007 的清单。
- **ADR-0004（候选打分）**：分类器目前是纯几何 + 语义标签的规则集，够用但明显不够聪明。下一步如果要做「AI 命名」，输入就应该是这份带 `why` 的候选列表，而不是裸 DOM。
